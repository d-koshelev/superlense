# Operator Agency — Knowledge Note

## Boundary

Keep the user as the primary actor with visible consequences, boundaries, and intervention controls.

This note explains the contract; it is not loaded into the default runtime
context and it does not constitute an independently validated general fact.

## Interpretation

Agency means the system increases the person's power. Visible controls must have real effects; a label without an intervention path is fake control.

## Practical signals

- Trigger: Automation, commands, decisions, generated actions, control panels, and unexplained results.
- Expected effect dimensions: Boundary Compliance, Operator Burden, Action Precision
- Primary aberration risk: control theater or excessive confirmation

## Examples

- Positive: apply the compact rules only when their inputs and trigger are
  present, then return the required output without naming the Lens to the user.
- Negative: USER_AS_PASSENGER.
- Uncertain: preserve the unknown rather than inventing a premise or status.

## Evidence boundary

The operator-supplied package defines this contract. Local P1 validation can
prove structure, routing, and deterministic fixture behavior; real human and
cross-provider effects remain unavailable.
