# Information Priority — Knowledge Note

## Boundary

Present information according to its importance, frequency, and moment of use.

This note explains the contract; it is not loaded into the default runtime
context and it does not constitute an independently validated general fact.

## Interpretation

The default response order is result, key evidence, necessary detail, supplementary data, then technical log. CRITICAL is exceptional and must not become ambient alarm noise.

## Practical signals

- Trigger: Responses, reports, dashboards, inspectors, forms, and decision surfaces.
- Expected effect dimensions: Focus, Report Fidelity, Action Precision
- Primary aberration risk: compression loss or hiding evidence from experts

## Examples

- Positive: apply the compact rules only when their inputs and trigger are
  present, then return the required output without naming the Lens to the user.
- Negative: FLAT_PRIORITY.
- Uncertain: preserve the unknown rather than inventing a premise or status.

## Evidence boundary

The operator-supplied package defines this contract. Local P1 validation can
prove structure, routing, and deterministic fixture behavior; real human and
cross-provider effects remain unavailable.
