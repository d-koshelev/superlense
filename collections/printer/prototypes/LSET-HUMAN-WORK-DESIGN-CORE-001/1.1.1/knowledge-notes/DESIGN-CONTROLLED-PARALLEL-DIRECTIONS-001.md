# Design Controlled Parallel Directions — Knowledge Note

## Boundary

Permit intentional A/B/C alternatives while preventing duplicate ownership, conflicting sources of truth, and permanent experiments.

This note is supporting rationale, not default runtime context or canonical
project state.

## Interpretation

Controlled parallel work is useful when differences are meaningful. The Lens governs the decision contract, not Git branches or canonical project storage. A SUPPORTED_VARIANT may coexist; an EXPERIMENTAL candidate needs an exit.

## Runtime evidence boundary

The compact contract is deterministic and testable. Local P1 validation does
not establish real human or cross-provider effectiveness.
