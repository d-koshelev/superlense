# Human Audience and Context — Knowledge Note

## Boundary

Adapt the work to the actual audience's role, expertise, task, and operating conditions.

This note explains the contract; it is not loaded into the default runtime
context and it does not constitute an independently validated general fact.

## Interpretation

Expert density requires hierarchy and rapid evidence access, not fewer facts. Novice guidance exposes one current step while keeping technical detail available without making it dominant.

## Practical signals

- Trigger: Any response, flow, interface, report, or handoff with a human audience.
- Expected effect dimensions: Context Quality, Action Precision, Operator Burden
- Primary aberration risk: stereotyping the audience or hiding exact evidence

## Examples

- Positive: apply the compact rules only when their inputs and trigger are
  present, then return the required output without naming the Lens to the user.
- Negative: GENERIC_USER_ASSUMPTION.
- Uncertain: preserve the unknown rather than inventing a premise or status.

## Evidence boundary

The operator-supplied package defines this contract. Local P1 validation can
prove structure, routing, and deterministic fixture behavior; real human and
cross-provider effects remain unavailable.
