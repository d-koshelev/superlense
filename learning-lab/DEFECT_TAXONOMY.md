# Defect taxonomy

Severity: `HARD_FAILURE`, `HIGH`, `MEDIUM`, `LOW`.

Confidence: `VERIFIED`, `PROBABLE`, `POSSIBLE`.

Root cause:

`IMPLEMENTATION_BUG`, `MISSING_REQUIREMENT`, `AMBIGUOUS_REQUIREMENT`, `TASK_SPECIFICATION_DEFECT`, `MISSING_LENS`, `DEFECTIVE_LENS`, `LENS_CONFLICT`, `LENS_OVERREACH`, `TOOLING_FAILURE`, `FIXTURE_FAILURE`, `EVALUATOR_FALSE_POSITIVE`, `OPERATOR_PREFERENCE`, `DELIBERATE_TRADEOFF`, `UNKNOWN`.

A record must identify exact observed behavior, evidence IDs, user consequence, violated requirement or lens, root-cause evidence, repair, regression tests, fixture requirements, and lifecycle. “Looks strange” is not evidence.
