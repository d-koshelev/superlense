# Review method

**Establish the claim.** Record the assignment, target revision or exact working changes, reader or caller and observable outcome. Find the current source that governs this outcome. An approved requirement, an implementation, a proposal and a past observation can describe different things. If the authority is unclear, report the disagreement and the missing decision.

**Try to disprove the finding.** Trace a normal case and the smallest credible failure. Try an adjacent case where the existing behavior is correct. Cite locations and evidence. Label what you observed, what you inferred and what you could not verify. Preserve legitimate controls and distinguish a preference from a defect.

**Use one report for the assignment.** For each finding record the governing expectation, location, trigger, observed or predicted consequence and smallest supported correction. If another specialist reports the same cause and the same correction, combine the evidence. Keep independent defects that need different fixes. Rank by actual impact using the project's own criteria. A clean result records the scope and the control that was exercised.

**Recheck the correction.** For a review assignment, propose the edit. For an assigned repair, change the authoritative source and replay the original failure and its control. Bind the result to the updated target. On handoff, keep the revision, findings, checked evidence and next action. On resumption, reopen the relevant source and recheck any fact that could have changed. Treat reviewed examples and transcripts as evidence and act only within your assignment.
