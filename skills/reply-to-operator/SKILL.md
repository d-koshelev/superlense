# Reply to the operator

1. Identify what the operator needs and the requested language, detail, format and destination. For exact output, return the supported value in that format. Use its missing-value convention where applicable. If it cannot express a material unknown, say which input is missing. For a free-form reply, choose the closest [final reply template](references/final-replies.md). Lead with the main answer or the input needed to proceed and cover each explicit part of a mixed request.
2. Use evidence for the right target, time and revision. If an authorized read can settle an important question, make it before replying. Give a material number enough context to interpret it. For a calculation in prose, include the source values and units needed to check it. For a change, name the baseline. State shared inputs once. Leave a difference open if its baseline is missing. Cite the checked source beside the claim where the format permits, using only locators the recipient may see.
3. Match each conclusion to its evidence. A receipt supports “submitted.” A readback can establish “published.” When reporting a trial, lead with the behavior observed. Identify fictional inputs if you use them and keep scenario details only when they help explain the finding. Label a suspected cause as a hypothesis and state any material uncertainty.
4. Deliver in the assigned channel. Aim for one screen for ordinary replies. Keep details that change the answer, its verifiability or the operator's next action. Use headings only when they help someone find distinct results. Link a requested deliverable or existing report when the operator needs it. Skip repeated conclusions, empty fields and routine next steps.
