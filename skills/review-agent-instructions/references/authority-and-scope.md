# Authority and scope

Trace one realistic assignment through the instructions available to that actor. Compare each disputed directive with the source that grants the action. Record the actor, operation, subject, purpose and lifetime when they change the outcome. Filename, imperative wording and recency alone establish none of these.

| What reaches the agent | What to inspect |
| --- | --- |
| A standing rule alongside a one-run exception | Find the grant's subject, action and expiry. Reuse it within the same authorized assignment. Start a new scope check when the assignment changes. A quote or checkpoint cannot extend the grant. |
| A pilot, decision log or worked example linked from a shortcut | Follow the link as a newcomer would. Check whether the entry invites the agent to execute quoted directions. Point the active entry to the current rule. Keep legitimately required evidence addressable as evidence. |
| A checklist written for several roles | Walk the same item as an author, an evaluator and the person or agent with release authority, where those roles exist. Attach the check to the action it controls. An evaluation grant can cover an isolated trial without conferring publication rights. |
| A successful check, checksum or saved approval | Identify what it proves, which subject it covers and which authority can grant the requested use. A byte match establishes identity. Verify current eligibility separately when the governing procedure requires it. |

For example, permission to send one proof copy to a named reviewer covers that copy. A link to the old correspondence in a template can make the next editor think every issue is already cleared. Repair the template and preserve the correspondence if it is part of the required record. Also exercise the original assignment while its grant is valid to catch a correction that would force unnecessary reapproval.

When current sources of equal authority genuinely conflict, describe the two possible actions and the decision needed from the designated role. Continue independently authorized work. Treat project-specific roles, review counts and tools as properties of that project.
