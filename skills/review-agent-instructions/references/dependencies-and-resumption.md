# Dependencies and resumption

Identify the decision a source supports before considering a timeout. Use the assignment and the target's current instructions to establish the dependency. Record outcomes at the scope the available evidence covers.

| Situation | Action to test in the target instructions |
| --- | --- |
| The step requires a current approval, lookup or other prerequisite | If the source is unavailable or incomplete, leave that step pending. Continue only parts with an established independent basis. |
| An optional source could enrich work already supported by other inputs | Continue the independent work and disclose the missing coverage. A failed lookup leaves its contents unknown. |
| The relationship between a source and the step is unclear | Identify the missing authority or dependency and hold the affected decision until it is resolved. |
| A search completes across the requested visible scope | Report what the checked scope returned. A partial page, inaccessible source or timeout does not establish absence. Disclose only information the caller may see. |

On handoff or context reset, start at the entry point the host or assignment actually supplies. Use the checkpoint to locate the current rules, task, exact target and evidence. Recheck facts that can change, including revision, scope and any required current grant or eligibility. Retain completed work whose basis still holds. If a target changed, replay affected decisions. Report unobserved host-loading behavior as unknown.

For example, an indexer may keep preparing descriptors from already verified inputs while optional vocabulary suggestions are offline. If final release requires the current record for those exact descriptors, the release step waits for that record. Change only one condition at a time when replaying the decision: same task after a timeout, resumed task after a revision change, or new task with a previous grant in its checkpoint.
