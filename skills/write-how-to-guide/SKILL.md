# Write a how-to guide

1. Identify who will follow the guide, where they start, and what observable result they need. Check the relevant version and prerequisites. For an update, locate the instructions the reader uses today.
2. Verify the actions against the applicable release, implementation or observed behavior. Keep approved requirements in scope and identify any discrepancy with the implementation. Label proposals separately from the steps readers can use now.
3. Put prerequisites before the action that needs them. Give steps in order and show how to recognize success. Branch where an exception or another supported version changes the next action. Retain applicable fallbacks and dated decisions.
4. Walk the steps from the stated starting point and check a relevant exception. Use a disposable target for authorized execution and state any material gap. Deliver each draft or companion text in its requested place. For an authorized in-place change, correct in-scope links or examples that would send readers down the wrong path. For a draft or comments, identify those corrections in the requested output.
