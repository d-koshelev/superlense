# Edit for the reader's next action

1. Identify the reader, what they need to decide or do, and the facts the source establishes. Preserve the requested language, voice and format. In a revision, keep requirements, permissions, exceptions, uncertainties, units, identifiers and exact commands intact.
2. Lead a reply with the answer or decision. For a procedure, put prerequisites before the first step that needs them, steps in execution order, and the observable result next to the action. Use a table when readers must compare cases. A short answer can stand alone.
3. Give each term one meaning. For a direction that could lead to different actions, name the actor, trigger, action and completion signal wherever the source supplies them. Keep optional and required actions distinct. If the source leaves a consequential choice open, state the unresolved choice separately and preserve the supported text.
4. Remove lead-ins, repeated conclusions and phrases whose deletion changes no decision or fact. Replay a normal case and any stated exception against the draft. Restore anything the shorter version would lose.

Return the finished text in the requested place. Put an unresolved question alongside it only when its answer changes the result. Create a separate document when the assignment calls for one.
